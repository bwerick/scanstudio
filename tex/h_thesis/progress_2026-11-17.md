# ScanStudio: Implementation and Initial Evaluation

Rohan Reddy Boddu | Honors thesis writing checkpoint | November 17, 2026

## 1. Background and scope

ScanStudio converts video recordings of books into digital page images and PDF documents. The workflow uses page-turn motion to divide a recording into candidate intervals, selects representative frames, and allows a person to review the selected images before cropping and splitting spreads. Its purpose is to make book digitization accessible without requiring removal of the book binding. This checkpoint describes the existing system, the advisory duplicate-detection addition, and an initial recorded-video evaluation. It is a progress report, not a completed validation of the system.

The proposal describes spring work as learning the codebase, reviewing book digitization and OCR, and identifying opportunities to improve the workflow. Summer activity involved following development, preparing the environment and hardware, and planning fall implementation. These activities establish context; they are not quantitative evidence that a new algorithm improves scanning. Earlier meeting notes describe three recordings of the same book, with qualitatively cleaner results on later attempts. Because the capture procedure and corrections were not controlled, those observations motivate systematic evaluation rather than a measured improvement claim.

The current thesis focus is reducing unnecessary work during frame review. Duplicate captures, partially turned pages, and hands covering content are different failure types. A duplicate repeats page content already captured; an occluded or mid-turn frame may contain unique content that needs recapture. Treating all rejected frames as duplicates would therefore obscure both the problem and the system's performance. Automatic missing-page coverage checks and OCR-assisted quality assessment remain proposed extensions rather than completed contributions.

## 2. Implementation checkpoint

The recorded-video path computes a motion signal, identifies page-turn peaks, and extracts keyframes from the resulting intervals. Phase 3.5 then compares nearby keyframes and records likely duplicates before Phase 4 human review. Subsequent stages crop spreads, split them into individual pages, provide a second review, and assemble the PDF. Human decisions remain part of this workflow; successful PDF generation does not imply fully automated digitization.

The added duplicate heuristic is image-based and does not run OCR. In the reviewed version, each frame is converted into a 96 by 96 grayscale preview and lightly blurred. A 64-bit difference hash captures coarse image structure, while normalized mean absolute pixel difference measures intensity changes. A later frame is flagged only when both comparisons pass their thresholds. Defaults compare against one previous keyframe, require a hash distance no greater than 4, and require a normalized pixel difference no greater than 0.02. These defaults are baseline settings, not experimentally optimized values.

The stage writes a JSON quality report and attaches advisory flags to keyframe metadata. It does not automatically delete images. The native review interface displays these flags, but the reviewed browser interface does not yet expose them. Since the remote experiment used browser review, displaying the same warnings there is a concrete integration task. This interface omission is separate from the experiment's zero computed flags: adding a browser label alone would not resolve the missed duplicates.

A separate compatibility repair restored crop helpers needed by the native keyframe reviewer. The earlier import failure occurred before its window could open. The remote experiment later completed through the browser workflow. These are distinct observations: an import repair and a completed remote run do not establish that every interface and cropping configuration has been validated. The implementation baseline for this report is repository commit `2c0ed7f`; the advisory quality pass was introduced in `336ec07`.

## 3. Recorded-video experiment

On November 9, 2026, the pipeline ran on Rolando's Linux machine, accessed through Tailscale and SSH. Browser review was accessed from the Mac through a forwarded port. The source recording was `30PagesOfCommunicationsOfTheACM_Vol67No1.mov`: 1280 by 720 pixels, 30 frames per second, 2,835 frames, and 94.5 seconds. Although a 4K camera is available for future work, this particular experiment used a 720p recording.

The run log records 17 detected motion peaks and 18 candidate intervals. Phase 3 extracted 18 keyframes. Phase 3.5 checked all 18 and reported zero likely duplicates. During human review, three frames were removed; the operator identified these as frames captured while pages were turning. Fifteen retained spreads, with zero covers tagged, produced 30 page images. The completed PDF contains 30 pages and is approximately 2.1 MB. The manual rejection fraction was 3/18, or 16.7%; this measures recorded human intervention, not duplicate-detector accuracy or recall.

Visual inspection of the resulting PDF found repeated content at PDF positions 7 and 9, and again at positions 8 and 10. These two pairs are consistent with one repeated spread surviving the workflow. Hands obscure text on some retained pages, particularly positions 7 and 20. Positions 1 and 2 split a cover image into halves with substantial background. Position 16 shows clipped content at the left boundary. The final PDF alone cannot determine whether that clipping originated in capture, crop geometry, splitting, or deskewing. The source frame and saved geometry must be checked before assigning a cause.

The PDF has no extractable text layer in the inspected file. Small text is also constrained by the input resolution and page framing. Increasing export resolution cannot restore detail absent from the source. A new, more tightly framed high-resolution recording is a suitable follow-up, but this report does not claim that test has occurred. Similarly, a 30-page output does not prove that all intended source pages were captured once and in order.

## 4. Evaluation and next deliverables

The experiment demonstrates end-to-end operation on the remote machine and identifies reproducible examples for improvement. It does not establish duplicate-detection accuracy, live-mode usability, OCR quality, or completeness. The main limitation is that the original 18 candidate frames and their identities have not been joined to a verified reference-label set for this report. Local metadata from an earlier run contains 14 frames and must not be substituted for the remote experiment.

The next evaluation should preserve the original candidates and label duplicate identity independently of image quality. Each candidate should record its source frame number, timestamp, page identity or identities, duplicate relationship, mid-turn status, obstruction, readability, and human disposition. The earliest occurrence can define the reference for duplicate counting, while a separate preferred-image field identifies the clearest capture to retain. This avoids confusing page identity with capture quality. Two output page pairs derived from one repeated spread must not be counted as two duplicate spread detections.

For duplicate evaluation, a true positive is a correctly flagged repeated candidate, a false positive is a unique candidate incorrectly flagged, and a false negative is a repeated candidate left unflagged. Precision is TP/(TP+FP), recall is TP/(TP+FN), and a zero denominator is reported as not applicable. No numerical precision or recall is reported here. Results should be separated by recording, with threshold tuning on development recordings and evaluation on a different recording. The observed repeated pages are useful development examples, not an independent test set after tuning against them.

The proposed next coding checkpoint has three parts: preserve original frames and review decisions; expose advisory flags and matching-frame details in browser review; and evaluate page-focused or aligned comparisons against the current full-frame heuristic. Repeated cropping currently risks altering already processed images, so preserving originals also protects reproducibility. A stable-frame quality filter is a subsequent candidate task. OCR-based occlusion detection and automatic coverage reporting should remain stretch goals until the core evaluation and written thesis are complete.
